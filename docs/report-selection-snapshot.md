# Saved active selection

New report builds capture active survey selection in the same authorized local-primary SQL statement as response evidence. This is a migration-free extension: `synthetic_report.capture_json` holds the strict tuple `["3d-report-selection-capture-v1", assessmentId, originalPackedResponseCapture, activeSurveys]`. Each active survey tuple holds survey ID, assessment ID, template ID/version, pinned perspective and source reference. Selection is bounded to the nine pinned template identities and the complete stored wrapper to 524288 bytes. Duplicate IDs/templates, unpinned identities and inconsistent selected/archive state refuse new builds.

Active means `state='selected' AND archived_at IS NULL`; collection open/closed is irrelevant. Deselecting an unused survey deletes it. Responses, access codes or invitations instead cause archive; reselection restores the existing survey ID. Archived responses remain in scoring exactly as before. Active selection is not evidence that a perspective was never asked.

The unchanged response capture remains the scoring input and response digest. Report-key-v2 separately binds its existing version tuple and the canonical active-survey selection digest. A selection-only change creates a distinct report; identical input and open/closed changes reuse it. The guarded INSERT compares the entire wrapper against a fresh same-statement capture, so response or selection changes before insertion conflict. No database columns, migrations, existing rows or scoring rules change.

Stored wrapper validation is independent of current selection. GET/LIST use the original response-only current eligibility boundary, retain fresh grants/authority checks, and validate the saved wrapper/key/payload. A malformed current zero-response selection cannot hide an otherwise eligible saved report. The exact two-array legacy decoder and v1 key preimage remain supported; old records have unknown selection and are never backfilled from current settings.

Only `report_selection: {schema:"3d-report-selection-v1", selected_perspectives:[...]}` reaches report payloads. Internal survey IDs, template tuples and capture bytes are not transported. Next saved readers and named/full PDFs use this saved projection; the Results collection hub remains live. Selected perspectives without captured responses show zero / More input needed. A missing active perspective is described as not selected at report capture where relevant, never never-asked. Archived responding perspectives retain their actual scores. Current-screen design and shared one-response admission/export remain unchanged.

The existing report/data-contract owner retains capture, identity and immutable-store custody; the report API owner retains the public projection and grants; the existing Next/PDF owner retains presentation and #608 reconciliation. This local engineering extension creates no new owner claim or publication authority. Future source/template changes must update the approved pin and selection validator together. Rollback of new wrapper writes must retain this reader for any already-created v2 records; reverting to an older reader would hold those records. The independent Summit threshold flag rollback remains documented separately.

Historical recovery still requires an authoritative immutable selection record tied to a specific report capture. Deleted unused surveys and previous selections of reselected rows cannot be reconstructed from current state or response absence. No historical reconstruction, live mutation, migration or fabrication is included.
