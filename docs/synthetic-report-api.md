# Authenticated synthetic report operations

This local integration activates only `cap.report.build`, `cap.report.get` and `cap.report.list`. It does not establish real-data reporting, UI completion, production readiness or remote migration execution. Source payloads retain three distinct lenses, missingness and source-authored narrative; this is not a new universal quality score.

Build is `write.effect` on the danger tool. POST `/v2/assessments/{aid}/reports` with `{"mode":"dry_run"}`, then `{"mode":"execute","confirm_token":"…"}`. MCP uses the same capability, params `{aid}`, modes and dispatcher. Preview includes impact, confirm_token and expires_in for both eligible and held states and writes no report or receipt. Confirmation binds actor, assessment, params and contract revision. It authorizes evaluation of current inputs at execute, not the preview's old cohort. There is no automatic build or retry.

Get is GET `/v2/reports/{id}` or read `cap.report.get` with `{id}`. List is GET `/v2/assessments/{aid}/reports?cursor=…` or read `cap.report.list` with `{aid,cursor?}`. Path IDs are authoritative. Unknown fields are rejected; IDs are nonempty and at most256 UTF-8 bytes. No caller chooses role, page size, renderer, version or payload. Session and protected first-party/delegated MCP bearer authentication remain existing platform mechanisms; participant credentials confer no report authority.

Exact assessment member/owner is required for preview/build; viewer-or-higher for get/list. Support needs its own exact grant. Policy's report branch terminates before the generic grant query, so store observation owns target, grant and complete current input capture together. Unknown/ungranted/archived targets and participant calls return the same report-not-visible error. Anonymous retains authentication failure. No parent-grant inheritance or support shortcut is added.

Eligible build/get returns `{assessment_id,suppressed:false,report:{id,created_at,payload}}`. List returns `{assessment_id,suppressed:false,reports:[{id,created_at}],next_cursor}`. Payload is the exact accepted `3d-synthetic-assessment-report-v1` source renderer output, verified against the original attested capture; current input eligibility is separately required on every disclosure. Known synthetic append can leave an old immutable report readable. Invalid original/current inputs or corrupt selected row suppress the entire page, including corrupt lookahead.

Held result is `{assessment_id,suppressed:true,status:"held",reason:"Report unavailable under the current synthetic reporting policy.",report:null,snapshot_version:null,algorithm_version:null,policy_version:"synthetic-current-assessment-asof-query-v1"}`; list uses reports:[] instead of report. No held report ID, cursor, count, digest, membership, timestamp or partial page is disclosed. Eligible preview is `{assessment_id,suppressed:false,status:"ready",report:null}` plus dispatcher impact/token/expiry. A held execute may receive the ordinary platform receipt; that receipt records completion of the operation, not materialization of a report.

Operational errors expose only STAGE_CONFLICT. Preview/get/list use `The report request could not be completed.` Execute build uses `The report build outcome could not be confirmed. Recheck reports before choosing to retry.` Internal store failure names never enter public errors. A lost response can follow a committed write. Same captured membership and version tuple converge to one row; changed input on a later user-chosen retry can legitimately create another key. No recovery of the original across changed inputs is promised.

Receipts retain platform actor/assessment scope/trace fields, inverse:none and the accepted compensating control. Actual private projection is prior:null, params:{}, result_ids:{}. Reports, hashes, answers, payloads and cursors are not receipt locators and must never be logged. The cursor/afterId redaction supplement is defense in depth, not permission to emit these values into diagnostics.

List has fixed five rows and one fully validated lookahead. Random immutable IDs sort in SQLite BINARY order. Cursor carries the last disclosed ID only; it traverses a live set, not a complete snapshot. Newly inserted keys before the cursor can be missed until a fresh walk. No totals or chronological ordering is implied.

Cursor format is cur1_ plus canonical base64url of nonce12||AES-GCM ciphertext/tag128. HKDF-SHA256 uses raw nonempty SESSION_SECRET, salt `3d-report-cursor-v1`, info `report-list.v1`. AAD is UTF8 JSON.stringify(["report-list.v1",actor,assessmentId]). Exact canonical plaintext binds actor/assessment, source/index root, scorer/narrative/policy/schema, afterId and expiry. Independent cursor TTL is300seconds. Tokens are limited to4096 UTF-8 bytes before decoding; malformed, wrong-domain/binding/secret, expired/future or invalid shape always yields INVALID_PARAMS / `Invalid report cursor.` without varying hints. Rotation invalidates cursors. Cursor validity never replaces fresh grant/current/stored checks.

Only three rows move from reserved to implemented-synthetic-only. At ingredient base83 operations remain: read29, effect8, reversible39, dangerous7; v2.0-bcs78/v2.1-oct5. Recommendation propose/review, project/workspace rollup and batch import remain reserved. Contract schemas are narrowly maintained; whole generator execution or manifest regeneration is not implied. Unrelated later contract changes require reviewed integration.

## Validation and release boundary

Local tests exercise actual Miniflare D1 and existing HTTP/MCP worker, strict cursor attacks, grants, confirmation, receipts, uncertainty, pagination/lookahead and all34 synthetic contexts. Existing C2a source/storage tests and nonreport Auth regression remain required on the combined candidate. Local Node timing or process memory is not Worker CPU/peak-memory proof.

There is no report.build-specific CAP_LIMITER entry. Authenticated HTTP rendering therefore has no newly added per-principal report limiter; existing applicable MCP/platform limits remain. Root must assess this known resource/security risk with effective runtime/transport evidence; no safe-throughput claim or invented rate is made. Remote0008 migration, DEV-only rollout, source/version observation, Design/browser acceptance and independent security review remain separate gates. Production is excluded.
