# 3d-review MCP Apps UI spike — isolated, fixture-only

Order: cookbook #16 c5719587147 · contract #16 c5719616259 · challenge folded #16 c5719669587.

**What this proves:** a tool round-trip rendered INLINE in the MCP Apps reference host (`ext-apps` `examples/basic-host` 2.0.0): `tools/list` carries `_meta.ui.resourceUri`, `resources/read` serves `text/html;profile=mcp-app`, `tools/call` → host renders the view → view receives the tool result (`toolresult` event registered before `connect()`). Screenshots and RPC samples in `out/`.

**What it does NOT prove:** live wiring (the real server exposes four generic tools — `docs/read/write/danger` — and no `resources/*`; this spike is a standalone demonstration, not a path onto `src/mcp.ts`); rendering in any host other than basic-host (the Claude host serves this profile to other connectors, which is observation, not a test); the sandbox/CSP restrictions recorded in `out/README.md` are basic-host implementation choices, not MCP Apps guarantees, and the `io.modelcontextprotocol/ui` extension capability was never negotiated (this host sent `capabilities: {}`); real authorization (role-awareness is the fixture's `role` field — hosts pass no principal); any write (`cap.survey.select/deselect` never called; "Preview selection" writes nothing; no Undo offered because no reversal is exercised).

**Data:** `fixture/assessment.json`, labelled in-view "Fixture data — not live"; shape copied from `cap.assessment.get` (`{assessment, surveys}`) plus per-survey `cap.survey.get_status` counts (N+1 in live wiring). `templates[]` follows the app's template-list snapshot shape documented at `ui/lens-surveys.js:60`, whose rows come from `migrations/0004_pinned_instruments.sql`. The error fixture is the app's real failure envelope: `src/envelope.ts` `fail()` shape (`{ok:false, error:{code,message,hint}, trace_id}`) with code `NOT_FOUND_OR_NOT_VISIBLE` and the message from `src/handlers/errors.ts` `notVisible("assessment")`; the overview renders code, message, hint and `trace_id`.

**Isolation:** own `package.json` (`@modelcontextprotocol/server@2`, `ext-apps@2`, `zod@4`); nothing under `ui/` (public assets); root `tsconfig`/`vitest` includes do not reach `spike/`; not built or deployed by the Worker; never calls a 3d-review URL (the DEV root appears only as the `ui/open-link` target string).

**Design-system reuse: PRESENT.** `ui/design-system/components.css` is scoped entirely under `.rv` (the app roots it at `ui/index.html`: `<body class="rv" …>`), so `build-views.mjs` emits `<body class="rv" data-view-state="loading">` and the views actually pick up the aurora ground, glass panels, type scale and primary button — visible in `out/overview-default.png`, asserted in `server.spec.mjs`. One deliberate edit to the vendored copy: the Google Fonts `@import` at `ui/design-system/components.css:4` is stripped, because the served resource must fetch nothing off-origin (`server.spec.mjs` fails on any `http(s)://` in served CSS `url()`/`@import` or HTML `src=`/`href=`).

**Known gap (Design):** the views do not follow the showcase app-flows page structure and do not apply host theming — only the light `:root` token values render, so a dark-mode host still gets the light ground. Next increment if the experiment continues.

Run: `cd spike/mcp-ui && npm ci && npm run build:views && node server.mjs` (streamable HTTP `:3001/mcp`), then basic-host per `out/README.md`; tests `node --test *.spec.mjs` (9 pass). Run artifacts — screenshots, `drive.json`, trimmed one-run `rpc-log.jsonl`, `rpc-samples.txt`, `host.log`, `server.log` — are committed under `out/`.
