# 3D Review working agreement

This app answers to [klappy/kitchen](https://github.com/klappy/kitchen). Fetch its current `health-code/HYGIENE.md` and applicable companions before work; this pointer does not freeze upstream law.

- **HYGIENE 3:** PR review and finished required checks gate every non-rail change. Follow live [cookbook HYGIENE §10](https://github.com/klappy/3d-review-cookbook/blob/main/HYGIENE.md#delivery-and-session-continuity) and [merger §4.2](https://github.com/klappy/kitchens/blob/main/boarding/runners/merger.md#4--each-pr-oldest-first): fresh independent exact-head review replaces the retired Bugbot service. Record the real current-head GitHub approval through the verified separate review identity; missing Bugbot is not a gate. All attached checks must finish; required checks must pass; adverse results and review findings receive dispositions. No self-issued override.
- **HYGIENE 10a:** deployment happens only through the Git-connected Workers Build. No seat runs a deploy or uploads a Worker version.
- **Topology:** `main` → existing DEV; `production` → production. Provider cutover remains separately gated; production promotion is a gate, not a person (kitchen HYGIENE 32; FIA path). Production promotes when DEV and staging are green on that exact head, Terry (`klappy-agents`) has submitted `APPROVE` at that head, oddkit challenge has run, and a non-author seat merges/promotes. The captain hears only when it is live (kitchen `rail/3-pass/2026-10-28-cos-delegated-execution-authority/RULING.md` 2026-11-06 08:24 ET: "I should never have to even approve a merge. It should just happen. I understand 6-9 months ago. But not anymore."; 08:26 ET: "lol, wait, I understand my approval on law merges. I have to at least know what’s changing, why, and see a progressive disclosure summary of it." — this promotion path is non-law, so it has no captain step). An explicit staging branch/app is optional future scope only if needed.
- **HYGIENE 19:** `package.json` is the version source. Production promotes the same semantic version, canonical release pin and product source already validated in DEV; no promotion-only bump. Actual fixes go through `main` and DEV first. Build/client evidence must prove the manifest-derived `<version>+<sha7>` stamp. The current cookbook HYGIENE §10 standing rule supersedes the earlier every-promotion bump requirement.
- **HYGIENE 35:** the work rail (work units, journals, planning, meals) lives in [klappy/3d-review-cookbook](https://github.com/klappy/3d-review-cookbook) — [`work/`](https://github.com/klappy/3d-review-cookbook/tree/main/work) and [`meals/`](https://github.com/klappy/3d-review-cookbook/tree/main/meals). This repo holds code, contract and release records only; do not add `work/` or `cookbook/` here. History before the move stays in this repo's git log.

The repo-specific procedure and current promotion hold are in [docs/release.md](docs/release.md). Read it before any release action. Do not interpret this documentation as lifting that hold or proving version-stamp machinery exists.
