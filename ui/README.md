# Temporary functional UI shell

This is an integration adapter, not the Design lane's visual system or approved copy. It uses the live `/v2` HTTP API only; no browser-only business logic or fixture responses. The Design lane may replace `ui/`.

Run the Worker separately with an ignored local `.dev.vars` containing independent `SESSION_SECRET` and 32-byte base64url `CODE_ESCROW_SECRET` (see `docs/code-escrow-local.md`). On a fresh local D1, apply `migrations/0001_init.sql`, then `migrations/0002_code_escrow.sql`, then `seed/synthetic.sql`; start `npm run dev`. Run `node ui/server.mjs` and open `http://localhost:5174`. The UI server serves this directory and proxies `/v2` to `http://localhost:8787`; it is local-only and has no deployment configuration. Set `UI_PORT` and `UI_API_ORIGIN` for other local ports.

Local synthetic demo: sign in as `demo.owner@example.invalid` using the `dev_only_code` returned by the Worker in `ENVIRONMENT=dev` (no email is sent). This reserved-domain seed fixture is provisioned and owns the synthetic project and Collect-stage assessment; it is not production identity provisioning. Create an assessment, select a template, explicitly move from Prepare to Collect, issue code IDs, preview credential-release impact, then confirm export to reveal code values once. Copy one code into the participant form, answer, review, submit, and recover the receipt after reload. Exported codes are not cached by this shell and cannot be recovered by repeating export. Results remain held/suppressed; link delivery and production authorization are not demonstrated. No real participant information or production keys should be used.
