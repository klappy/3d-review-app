## Two precise amendments before FIRE

1. Make first-party eligibility executable. The plan excludes OAuth/delegated callers but resolvePrincipal exposes delegatedBy only for bearer transport; cookie-selected sessions suppress that field, and support sessions expose supportActor instead. Therefore a kind/delegatedBy check alone does not establish the stated exclusion. In the already-allowed index.ts read branch, inspect the selected session's stored kind/delegated_by via sessionTokenHash, or specify an equivalently complete rejection rule without modifying shared auth.ts. Bind this inspection to the same selected credential and preserve bearer precedence; reject missing/expired/replaced session and delegated metadata regardless of transport. Add route tests for delegated token as bearer AND cookie, and support/delegation eligibility. Do not claim all st_ credentials were minted by Access: the stored schema lacks that provenance. Define the allowed existing first-party session contract honestly; do not add provenance storage silently.

2. Explicitly generation-bind logout and switch completions, not only account-email reads. Capture identity generation/credential at action start; a late successful logout for old identity must neither clear a newer identity's client state nor navigate it to provider-wide logout. The old request may already have revoked its presented server credential, so do not call it canceled or undone. Add deferred logout and deferred switch tests that replace identity before success/failure resolves; assert no new-identity clear/navigation and truthful status. Busy/double-click tests alone do not cover this. Implement within already-listed assess.js/identity-reset.test.mjs.
