## Required corrections

**P1 — no automatic identity replacement based on missing local marker.** Failed resume is not observed storage loss. A notice displayed after minting a different respondent does not preserve the original context or establish the participant chose a new response. In particular, absence of a submitted marker is not proof of an unsubmitted context: the server may have committed but the success reply was lost; storage.set can fail; the old UI never wrote that marker. Retrying without resume then restores the old answers into a fresh identity, inviting a second response after an uncertain first outcome. The contract deliberately guarantees per-context response identity, not deduplication across newly minted contexts. Retain old bearer/draft/key until explicit restart choice; do not reinterpret unknown completion as unsubmitted.

**P2 — neutral, evidence-bound copy.** NOT_FOUND_OR_NOT_VISIBLE cannot establish “previous session expired”; it may mean unknown/revoked/cross-link session or unavailable link. Even a successful fresh open establishes only that the link permits a new context, not why the old context failed. A second failed attempt does not prove a dead link: it can be STAGE_CONFLICT,429 or transient/transport failure. Preserve existing distinctions and uncertainty. A scoped marker written only after confirmed success can support “this browser previously received submission confirmation,” not an authenticated current receipt, current record existence or an expiry diagnosis. Marker absence proves nothing about server commit. Do not show fabricated response identity or another context's receipt.

## Minimum safe owner correction

1. Keep API and its generic refusal unchanged. On refused resume, show a neutral cannot-resume state; make no new open automatically, and preserve the old context/draft/key. No transport error,429 or STAGE_CONFLICT should trigger identity replacement.
2. If Auth/Design retain a recovery action within this bounded correction, make starting a fresh response an explicit informed choice after refusal, warning that any previous submission cannot be checked and a fresh response is separate. This is recovery after failed resume, not kiosk Next or a new person-uniqueness policy. Route exact source copy and state transition through existing Auth/Design custody before implementation; the present automatic-retry ruling needs revision.
3. After that explicit choice, clear the abandoned bearer and submit key in memory and its scoped storage, then make one new open with the actual link token, cookies omitted. Create a fresh submit key only for the new context. Do not claim a fragment-free reload can recreate a link token from its digest. If the raw link is no longer available, ask the participant to reopen the original link; do not start persisting raw link credentials as an incidental fix.
4. If the fresh open succeeds, show truthful new-context copy. Offer draft restoration only after fresh form template/version match, with no implication it is a retry of the earlier submission; never restore a receipt. Keep unknown-outcome drafts distinguishable until the choice. If it fails, handle the actual error category without a dead-link assertion.
5. A historical confirmed-submission marker may improve explanatory copy but is optional evidence, not an authorization or duplicate-prevention oracle. Scope it to the same context/link, and do not allow it to suppress uncertainty for marker-free older sessions.

Focused acceptance cases for Design/fresh reviewer: expired and revoked stored sessions with valid link cause no automatic second open; explicit restart creates a new identity/key; server-committed submit with lost response and no marker does not silently become a second respondent; marker write failure/old UI marker absence remains unknown; valid historical marker is not shown as current server receipt; link revocation and STAGE_CONFLICT/429/transport failure remain distinct; fragment-free reload lacks a reconstructable raw link; cross-link namespace and template mismatch controls remain intact.

No new API discriminator, validation weakening, participant account/code, mandatory demographics, duplicate-per-person policy or kiosk Next is needed. Auth owns the contract re-ruling; Design owns source copy and implementation.
