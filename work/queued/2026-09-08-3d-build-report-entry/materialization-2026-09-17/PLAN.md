A final disclosure read revalidates current authority before any result or report identifier is returned.

## Complete capture and membership

Membership starts from every response whose survey belongs to the target assessment; do not filter archived surveys or successful template matches. LEFT JOIN selected and response templates, retain mismatches and reject them in attestation. Empty sets refuse. Because orphan rows cannot safely be assigned to a target, each boundary includes a global integrity predicate that refuses if any response lacks its survey, that survey's assessment, its own template or the selected template. This is conservative failure, not hidden omission. Candidate must measure its cost and prove it with actual schema corruption fixtures.

Each packed response tuple includes response ID, assessment ID, survey ID, response template ID/version, selected template ID/version, exact submitted_at and exact answers_json. Templates are distinct by selected ID/version and carry exact source_ref, perspective and items_json. Arrays are ordered deterministically by IDs/version using SQL BINARY ordering for stable raw capture comparison. Attestation independently enforces its UTF16 ordering and exact pinned identities; the SQL token is a concurrency token, not its canonical digest. No source='synthetic' label, ID prefix, provenance flag or mutable title confers eligibility.

Before aggregation, SQL checks counts and each raw/scalar length. Per-row packed fragments are built only from bounded strings; aggregate byte sums are checked before whole capture assembly. The final UTF8 byte length is checked again in SQL and worker. A selected template mismatch or unsupported shape fails closed. No LIMIT on response enumeration, slicing or pagination can masquerade as complete eligibility.

## Exact boundary contracts

**Capture for build:** one SELECT returns the assessment's bounded packed capture only when assessment exists and is not archived, principal kind is user/support, and the exact assessment grant is owner or member. Support has no bypass. Project/workspace roles do not inherit. All integrity and bound predicates are in this same statement. Runtime maps immutable copies to CaptureRow and attests before rendering. There are no later mutable reads for source inputs or display context.

**Guarded build:** render only through the separately reviewed deterministic renderer from this eligible capture. Validate output schema, version tuple and size; compute report key and payload hash. One `INSERT … SELECT … ON CONFLICT(assessment_id,report_key) DO NOTHING` includes fresh exact owner/member grant, nonarchived assessment, integrity/bounds, and raw current packed-capture equality to the originally captured token. Do not use broad INSERT OR IGNORE: unexpected constraints must fail visibly internally. If inputs change during rendering, zero inserts is a conflict unless a subsequent authorized exact-key read proves an already existing identical report. Never retry against new inputs invisibly.

**Build result:** whether newly inserted or duplicate, perform the same secure disclosure SELECT as get, selected by assessment/report key, requiring owner/member for the build response. It captures stored report and complete current input simultaneously. Attest BOTH original stored capture and current capture; verify stored identity/version/payload digest, then return only approved metadata/output. A mixed append or revoked grant after insertion can therefore withhold a result even though a safe immutable row was written. Treat an interrupted/withheld result as uncertain, not proof no write occurred. No report ID/count leaks through an error or receipt. Existing consent token semantics and dry-run payload are resolved by the contract owner, not improvised inside this module.

**Get:** resolve report→assessment inside the same SELECT; select report plus current capture with exact viewer/member/owner grant and nonarchived assessment, global integrity and bounds. The caller need not know assessment ID, but receives no existence signal when unknown or ungranted. Verify approved stored versions and original capture independently from current capture. Known additional synthetic rows may change current digest without invalidating old output; unknown or mutated current rows refuse. No mutable queries after this capture; async hashing uses captured strings only.

**List:** one SELECT observes the authorized assessment, complete current capture and ordered materialized rows for a bounded page. Return at most5 plus one internal lookahead; current and every selected original capture must attest before exposing any page. Unexpected unsupported/corrupt rows cause a uniform held result, not a partially filtered page or diagnostic count. No total count. Cursor is an opaque authenticated/encrypted transport token in the later contract layer, bound to principal, assessment, version tuple, last eligible report ID and expiry; it is never authorization and cannot contain visible held membership. Every page reruns the full current grant/archive/eligibility boundary. Internal B API takes validated afterId/page size; it does not introduce a public cursor codec or token endpoint. Until C supplies the approved cursor contract, public list remains reserved.

**Linearization:** reads authorize disclosure as of their one primary SELECT. A revoke/mixed append before that observation refuses; a change afterward blocks later requests but cannot retract an already authorized captured response. This is the settled as-of-query policy, not instantaneous revocation. Builds additionally require capture equality at the guarded INSERT. A later disclosure uses its own fresh single observation. No pair of independent JS reads is described as one snapshot.
