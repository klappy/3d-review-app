## Compatibility, failure and rollback

0006 creates a new table/index only. 0007 adds a nullable column (existing sessions remain NULL), indexes only new non-NULL shared sessions, and creates a new claim table. No existing row is rewritten or deleted by these files. Existing explicit-column inserts remain compatible before new shared-context traffic, and old runtime cannot create non-NULL invitation_id values. Verify current deployed source before executing; this pre-promotion compatibility does not establish a safe post-promotion rollback target.

No all-or-nothing remote-file guarantee has been established in this audit. Treat each migration as potentially partially applied on transport/error interruption. Never add BEGIN/COMMIT or alter reviewed SQL ad hoc. On any error or lost result: stop runtime promotion, read exact schema and counts; do not blind-retry 0007 (ALTER and indexes are non-idempotent), drop objects, or rerun earlier files. A separately reviewed forward-only completion containing only demonstrably missing DDL is required. Successful additive schema may remain while old runtime continues. If current runtime is affected, stop writes and escalate to root/Auth before action.

Before permitting any shared-context traffic, root must record a reviewed shared-aware rollback candidate that preserves link revocation/expiry, scoped session authorization and atomic response-claim enforcement, or a concrete verified mechanism to quiesce all participant reads and writes until separately reviewed recovery. Mere staff/testing-owner agreement is not proof of a public participant traffic block. Once shared contexts exist, rollback to 10f5 or another legacy runtime that lacks those checks is prohibited while participant traffic remains reachable: preserving rows alone does not preserve security. Recovery uses the governed release mechanism, leaves additive schema and collected data intact, and verifies the shared security acceptance or effective participant isolation before reopening. No downmigration. A Time Travel restore can discard intervening data and is outside this authority; recording its bookmark does not authorize restore.

0005 is excluded because neither selected source contains it. If integration deliberately adds the report candidate with 0005, stop and amend this exact manifest/compatibility/postconditions under independent review first; do not silently apply it based only on filename order.
