# A8 DEV recovery procedure — Git only, proposed for independent review

This clarifies accepted rollout1c780e37 and bounded source reviewf850aa4d. A prebuilt rollback Worker version is **not required** to release. The required property is a reviewed executable path that retains shared security and data. An accepted current shared-aware release may remain running while the existing owners prepare a reviewed Git fix. This is slower than a version switch; it is not unsafe merely because recovery takes time. No manual deployment, provider version rollback, force-reset, branch-protection bypass or production action is authorized.

Do not manufacture an outage or new infrastructure prerequisite for an otherwise secure current release.

## If continued traffic is unsafe

If observed evidence shows authorization bypass, corrupting writes or another active security defect, keeping that runtime reachable is not acceptable merely to wait for review/build. Root coordinates incident containment while owners prepare the same protected Git recovery; there is no promise of zero recovery latency or an already-tested kill switch.

Read-only provider discovery found an existing primitive, not new architecture: POST `/accounts/{account_id}/workers/scripts/3d-review-dev/subdomain` accepts `{enabled:false,previews_enabled:false}`. Fresh GET observed both currentlytrue. Account Worker Domains inventory returned27/27 and no custom domain mapped to3d-review-dev. This primitive disables the public workers.dev and preview URLs; it is whole-DEV ingress control, not participant-path-only control. It does not establish coverage of zone routes, service bindings or other ingress. No such write or end-to-end block test has been performed. Do not call it “verified isolation.”

If containment is needed, root first scopes a separately reviewed exact DEV control-plane action with actual executor: complete current ingress inventory (including zone routes/service callers), preserve current settings, identify how all participant reads/writes will be denied, stop/reconcile in-flight requests, execute only within recorded authority, and prove HTTP refusal on all discovered paths. This is not a deployment and does not change production, but it remains a separate provider mutation requiring root disposition; this proposal does not fire it. A sole workers.dev switch is insufficient if another ingress remains. Failure/refusal is an incident requiring immediate root escalation, not grounds to bypass checks or serve legacy10f5. Re-enable only after the secure Git-deployed recovery and ingress readbacks pass. No automatic re-enable/retry is assumed.

For ordinary release: independently accepted final integrated source/security and exact checks; verified additive DEV schema/config; published compatible source referencead95321; recorded owner/root Git-only recovery procedure above with its build/review latency acknowledged; actual final deployment and acceptance receipts. A second predeployed version and a newly built isolation system are not prerequisites. If the final candidate has a known security failure, do not open traffic; fix it first. If an incident later makes current traffic unsafe, containment must be proven before claiming isolation. Unknown future incidents are not silently converted into a mandatory new architecture project.

The accepted invariant remains: never restore a reachable shared-unsafe legacy runtime after shared contexts exist. Forward repair while the secure current release remains running satisfies that invariant. Independent reviewer must disposition this clarification before root records the recovery plan gate closed.
