## Compatibility and acceptance boundary

MINOR: additive normal-entry UI capability using existing report preview/build/list/get endpoints. No backend, scorer, grant, synthetic-admission, non-fixture-reporting, instrument, migration, seeding, provider or permission-policy changes. Owner/member at the exact assessment can request preview; only a ready current-scope preview enables explicit build. Viewer retains list/get only. Held inputs remain held. Existing report renderer and provenance are unchanged.

Confirmation is memory-only and consumed once. Expiry, identity/navigation invalidation and held/refused/malformed outcomes cannot execute. A lost/uncertain build outcome requires refreshing reports before another preview; no automatic write retry. Beginning a new preview removes the old report disclosure and invalidates an in-flight open. Successful build refreshes the server list for explicit reopening; refresh failure preserves the fact that build succeeded.

Local DOM tests establish the owner preview→confirm→list→reopen path, unchanged synthetic provenance, viewer control exclusion, held/malformed/refused/expired preview, cancel, repeated click, uncertain write and stale identity/navigation responses. These are automated local UI evidence, not current live fixture/report builds or human acceptance. Non-fixture reporting remains a separate held policy decision. No live report write or seed replay is authorized by this record.
